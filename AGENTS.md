# FireProt working instructions

Read `README.md`, `docs/architecture.md`, and `.agents/project_context.md` first. Respond to this project's user in Chinese. Write repository README files, architecture documents, and new project declarations in English. The existing Chinese Protenix baseline notes may remain untranslated.

- FireProt aims to become an AMD GPU protein structure inference framework. Protenix and AtlasFold have validated adapters; OpenFold3 has qualified strict deterministic FP32 paths. Biohub ESMFold2 including ESMC has a separate monomer adapter with exact-output qualification; its measured development recipe differs from upstream defaults. Original ESMFold v1, OpenFold2 and others remain future adapters. Preserve each model's semantics, and verify workload-specific compatibility and performance claims before making them.
- The top-level repository records framework code, cases, scripts, provenance, and documentation. `Protenix/` is an independent upstream Git checkout. Review and commit model-source changes inside `Protenix/`; do not add it as a top-level submodule or gitlink.
- Weights and CCD resources in `runtime/` live on DiamondHill. `outputs/` contains generated predictions. Do not add either directory to top-level Git.
- `scripts/infer.sh REQUEST PROFILE` delegates to Rust inference; `scripts/smoke.sh [MANIFEST]` delegates to Rust batch inference. Historical Python launchers are archived under `.agents/legacy_*`. `scripts/sync_to_diamondhill.sh` synchronizes local source and cases. Check the destination and changes before synchronization; it does not transfer remote weights, outputs, or Git metadata.
- The current baseline is Protenix v1.1.0 (`d3b4db6a121dd4584edd85e93744239325a2b72e`). Do not describe unmeasured optimizations as results.
- The eight `cases/` examples are development cases, not an independent test set. For experimental-coordinate metrics, use only `coordinates[mask]` from `gt_mapping.npz`; `reference` is an input reference conformation.
- Record model, input, dtype, cycle, step, sample count, random state, and cache state for performance or accuracy comparisons. `provenance/smoke_report.json` only establishes that three models loaded and produced finite coordinates.
- Historical Protenix setup is in `.agents/protenix_baseline.md`. `docs/architecture.md` distinguishes implemented boundaries from proposed contracts; the complete framework is still in migration. Maintained Python lives under `python/fireprot`, native sources under `kernels/amd`; `fireprot/__init__.py` is an import shim; historical source paths are mapped explicitly. Preserve `provenance/layout_path_map.json` as migration evidence.

- Work directly on `master` for future development, as explicitly requested by the user. Keep `master` as the GitHub default branch; do not create routine feature branches unless subsequently requested.

- User-selected promotion policy (2026-10-19): length-independent optimizations and computation reuse may be generalized after two distinct lengths actually exercise the treatment and pass correctness checks. Do not retain exact-length allowlists merely because only two points were measured. Preserve semantic/source/dtype/layout/lifetime guards and native fallbacks. Shape-specialized kernels still require their own valid dispatch domains. Two-point promotion is a deployment policy, not proof of correctness or speedup at every length; preserve platform/provenance boundaries and never count a native-only fallback as a reuse validation point.
